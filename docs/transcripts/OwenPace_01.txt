● Here's the full feature breakdown, built from the brief and ordered so each
  step has a working foundation under it. Given the stack mismatch, step 1 is

  Plan

  Foundation
  1. Backend migration: Express → NestJS (modules/controllers/guards), keeping
  existing Prisma/Postgres and current players/teams/stats routes working
  throughout.
  2. Auth migration: Passport local-strategy → BetterAuth with Google OAuth;
  RBAC re-expressed as Nest guards.
  3. Frontend foundation: wire up TanStack Query for data fetching and shadcn/ui
  for components; add the Google sign-in flow against BetterAuth.

  Basic tier
  4. Event schema & derivation: formal Zod event schema per sport,
  confirm/extend stat derivation to compute strictly from GameEvent rows (not
  pre-populated boxscore totals) — this is the platform's core per the brief.
  5. Submissions (single fixture): approved-submitter roles, submission windows,
  schema validation with descriptive rejection errors, traceability from stat →
  submission → events.
  6. Public API (basic): fixtures/events/derived-stats endpoints with filtering,
  pagination, stable IDs, filtered-slice export.

  Intermediate tier
  7. Batch pipeline: stage-and-validate batches, idempotent resubmission,
  resumable partial failures, review-before-publish, correction history.
  8. Aggregates & incremental recompute: season/career/competition aggregates
  via BullMQ, recompute only what a correction touches, reference-result checks.
  9. Scale & performance: seed hundreds of fixtures/events, indexing/schema
  tuning to hit a stated response-time target, Redis-backed caching.
  10. API governance: versioning, API key issuance, Redis rate limits/quotas.
  11. Dataset releases: versioned snapshot exports with schema docs + checksums.

  Advanced tier
  12. Custom statistic definitions: analyst-defined derivations over the event
  schema, validated, sandboxed, versioned.
  13. Live/streaming submission: in-progress-fixture feed, out-of-order event
  handling, replay determinism.
  14. Point-in-time & diff queries: "as of date" stats, release-to-release
  diffs.
  15. Async jobs & change feed: job-based large requests, incremental change
  feed.
  16. API lifecycle management: deprecation path, contract tests, per-consumer
  usage visibility.
  17. Data integrity & reconciliation: anomaly flagging, submitter
  reconciliation, correction propagation.

  That's 17 steps — happy to merge/reorder any of these if you'd rather group
  differently. Starting on Step 1: Express → NestJS migration now.
